# v0.4 검증 기록

2026-11-17. 실행한 결과만 기록한다. 이전 기록은 [v0.3](archive/VALIDATION-v03.md)에 보존했다.

## 실행 결과

- `npm run build`: TypeScript·Vite 통과. Three.js 청크 547.42 kB(압축 전) 크기 경고가 남으며 빌드 실패는 아니다. 면광원 LTC는 별도 지연 청크다.
- `npm test`: **36/36 통과**. 기존 27개 유지, 9개 수치·재생·캐시·데이터·장면 검증 추가.
- `CHLADNI_TEST_PRODUCTION=1 npm run test:browser`: **6/6 통과**. Chromium SwiftShader에서 실제 Worker와 빌드 결과 사용. 스크린샷 기준 갱신 후 갱신 옵션 없는 회귀 실행도 통과했다.
- `npm run benchmark`: M5 실제 Metal GPU, 6개 렌더 조건 + 전체 UI 2개 조건 실행. 페이지/콘솔 오류 0개.
- `git diff --check`, Prettier 검사 통과. 이 저장소에는 GitHub Actions 워크플로가 없다. CI 사용량 제한은 코드 오류로 분류하지 않는다.

개발 서버 기반 검사 중 한 번 문서가 재로드되어 공진 선택 검사가 중단됐다. trace에서 두 번째 문서 탐색을 확인했고 자동 갱신이 없는 production preview로 전환해 전체 검사를 통과했다. 추가 경계 테스트의 첫 fixture가 허용 판 크기보다 작아 거부됐으며 유효한 100 mm 판으로 수정했다.

## 성능 측정

Apple M5·16 GB·Chromium 153.0.8010.12·ANGLE Metal. 렌더러 하네스는 1200×700 CSS px, 표준 DPR 1.5(1800×1050), 저사양 DPR 1이다. 자동 품질 변경을 끄고 18프레임 워밍업 뒤 3.5 s 측정했다. 249.625 Hz에서 실제 1 s 실험을 120 Hz로 적분하고 20 Hz 기록을 반복 보간 재생한다. FPS는 rAF 프레임 간격이며 약 60 Hz 상한이 있다. GPU 시간은 disjoint가 아닌 EXT_disjoint_timer_query_webgl2 표본이다. CPU 제출 시간은 동기 GPU 대기를 포함하지 않는다.

100k는 50k 대표 입자 확장이다. 50k보다 독립 물리 입자가 많지 않으므로 기록 크기도 같다. 50k/100k의 GPU 시간 차이는 한 번의 짧은 측정과 GPU 부하 변동을 포함하며 성능 순서를 보장하지 않는다. 첫 FEM/스윕 준비는 162.3 ms, 이후 같은 모드를 재사용했다.

전체 앱은 1600×1000 창, 실제 3D 캔버스 1242×618 CSS px·DPR 1.5·20k 입자·8 s 실험에서 각각 3.5 s 측정했다. Glass·React·물리 시간 표시와 분석 통계를 포함하며 하네스 워밍업 조건과 다르다.

| 전체 앱 |  FPS | 평균 / P95 프레임 ms | 주 JS heap MB |
| ------- | ---: | -------------------: | ------------: |
| 실험    | 56.3 |        17.76 / 16.70 |          97.1 |
| 분석    | 60.0 |        16.67 / 16.80 |         107.5 |

MB는 10⁶ bytes. heap은 performance.memory의 주 스레드 표본이며 Worker heap/전체 프로세스 메모리가 아니다. GPU 값은 버퍼·텍스처·RG16F 그림자/깊이 할당의 추정이고 실측 VRAM이 아니다. 기본 프레임버퍼·드라이버·전역 LTC는 제외한다. 해제 후 Three.js 내부 계수는 모든 하네스 조건에서 geometry 1·texture 3으로 동일했다. 앱 소유 자원과 그림자를 dispose하고 컨텍스트도 해제한다. 이 짧은 반복으로 장시간 누수나 열 안정성을 검증했다고 주장하지 않는다.

[원시 JSON](../artifacts/v04-performance-metal.json)에는 업로드 bytes, Worker 왕복, 질량·이동 판정, GPU 표본 수와 백엔드가 있다. 재현: 개발 서버를 켠 뒤 `npm run benchmark`. macOS 기본은 Metal이고 다른 환경에서는 `CHLADNI_GPU_MODE`로 ANGLE 백엔드를 지정한다. Chromium 경로가 다르면 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`를 지정한다.

## 남은 한계

- 공기/역 클라드니, 입자 충돌·건식 마찰 접촉, 실물 보정·분리 효율 예측은 없다.
- 33개 준정상 장의 복소 보간은 빠른 chirp 과도응답이나 좁은 공진의 적응적 추적이 아니다.
- 실제 CAD/사진 정합, 광학 DOF/굴절, 절단면 캡, 완성된 GLB 가져오기와 영상 녹화는 없다.
- 위치/거리 원자료는 Float32 기록 정밀도다. 96 MiB는 체크포인트 예산이며 결과 전체 메모리 상한은 아니다. 긴 실험은 기록률이 내려간다.
- 바이너리는 전체 세션을 한 번에 읽는다. 파일 입력 상한 256 MB. 큰 JSON 인코딩은 주 스레드에서 수백 ms 이상 멈출 수 있어 장시간 기록의 Worker 인코딩·부분 로드는 후속이다.
- 일반 데스크톱 전체와 실제 저사양/모바일 GPU에서 60fps를 보장하지 않는다. Safari/Firefox·실기 모바일 열화·장시간 실행은 미검증이다. 모바일 캡처는 뷰포트/LOD/가독성 검증이다.
